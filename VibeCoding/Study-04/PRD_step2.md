# PRD 2단계: 재료 기반 레시피 생성

## 1. 목적
1단계에서 확정된 재료 목록을 입력으로, 텍스트 모델이 만들 수 있는 레시피를 추천·생성한다.

## 2. 사용 모델 (확정, 2026-11-23 호출 검증 완료)
| 용도 | 모델 | 비고 |
|---|---|---|
| 레시피 생성 | `nvidia/nemotron-3.5-lightning:free` | `/chat/completions`, 추론 모델 |

- 추론 모델이라 `max_tokens`가 작으면 추론에 토큰을 다 써서 `message.content`가 `null`로 온다. **`max_tokens` 1500 이상**으로 설정한다(검증 시 간단한 질문에도 추론 토큰 676개 사용).
- 429/타임아웃 시 재시도(최대 3회). 폴백이 필요하면 `nvidia/nemotron-3-ultra-550b-a55b:free`(목록상 무료 텍스트 모델)를 후보로 하되, 도입 전 호출 검증이 필요하다.
- 이전에 검토한 임베딩 모델(`nemotron-3.5-embed-8b`)은 생성 불가라 사용하지 않는다.

## 3. 사용자 스토리
- 사용자는 확정된 재료로 "레시피 추천 받기"를 누른다.
- 사용자는 추천 목록(2~3개)을 보고 하나를 골라 상세 레시피를 본다.
- 사용자는 조건(인원수, 조리 시간, 못 먹는 재료, 난이도)을 지정할 수 있다.

## 4. 기능 요구사항
1. **입력 구성**: 확정 재료 목록 + 선택 조건 + "가진 재료 위주, 기본 양념(소금·간장 등)은 있다고 가정" 규칙.
2. **출력 구조(JSON)**:
   ```json
   { "recipes": [ {
     "title": "", "summary": "", "servings": 2, "time_minutes": 20, "difficulty": "easy|medium|hard",
     "uses": ["계란"], "missing": ["대파"],
     "steps": ["..."]
   } ] }
   ```
   `uses`는 보유 재료, `missing`은 추가로 필요한 재료다. 파싱 실패 시 1회 재요청.
3. **환각 방지**: 목록에 없는 재료를 핵심 재료로 쓰지 않도록 프롬프트에 명시하고, `missing`에 분리해 표시한다.
4. **UI**: 추천 카드 → 상세(재료, 단계, 소요 시간). 생성 중 로딩 표시, 재생성 버튼.
5. **언어**: 한국어 출력.

## 5. 비기능 요구사항
- 키는 서버에서만 사용(1단계와 동일). 요청에 `:free` 접미사 유지.
- 응답 목표 시간 60초 이내(추론 지연 포함), 스트리밍 응답은 후속 과제.
- 프롬프트 인젝션 방어: 재료명은 데이터로만 취급하고, 길이·문자 수를 제한한다(재료당 40자, 최대 30개).

## 6. 안전·면책
- 알레르기, 익힘 정도 등 식품 안전은 모델이 보장하지 않는다. 화면에 "AI가 만든 레시피이므로 확인 후 조리" 문구를 표시한다.

## 7. 범위 밖
- 영양 성분 계산, 장보기 목록 자동 생성, 레시피 이미지 생성.

## 8. 성공 기준
- 같은 재료로 요청 시 유효한 JSON 레시피 2개 이상이 반환된다.
- `uses`가 입력 재료의 부분집합이다(수동·자동 점검).
- 빈 `content`(null) 응답이 발생하지 않는다.

## 9. 열린 질문
- 추천 개수와 조건 입력 항목의 최종 범위.
