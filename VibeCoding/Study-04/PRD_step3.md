# PRD 3단계: 사용자 프로필과 레시피 저장

## 1. 목적
사용자가 프로필을 만들고, 마음에 드는 레시피를 저장해 나중에 다시 볼 수 있게 한다. AI 호출은 없고 저장·조회 기능이 중심이다.

## 2. 전제
- 학교 실습용이며 집에서 혼자 사용하는 소규모 앱이다. 따라서 외부 소셜 로그인과 운영급 보안은 범위 밖이다.
- 단, 최소한의 보호는 유지한다(아래 5절).

## 3. 사용자 스토리
- 사용자는 프로필(닉네임)을 한 번 만든다(로그인 없음, 앱 전체에서 단일 프로필).
- 사용자는 2단계 결과 화면에서 "저장"으로 레시피를 프로필에 저장한다.
- 사용자는 저장 목록을 보고, 상세를 열고, 삭제한다.
- 사용자는 프로필에 못 먹는 재료·기본 인원수를 저장해 2단계 조건에 자동 반영한다.

## 4. 기능 요구사항
1. **프로필**: 닉네임(필수, 최대 20자), 선호 설정(못 먹는 재료, 기본 인원수). 수정 가능.
2. **인증 없음(결정됨)**: 로그인·PIN·세션을 두지 않는다. 앱은 로컬(`127.0.0.1`)에서만 실행하는 것을 전제로 한다. 외부에 노출하면 누구나 저장 데이터와 API 키 사용량(프록시 경유)에 접근할 수 있으므로 공개 배포 시에는 인증을 반드시 추가한다.
3. **레시피 저장**: 2단계 JSON을 그대로 저장하고, 저장 시점의 원본 재료 목록과 생성 일시를 함께 기록한다.
4. **목록·검색**: 최신순 목록, 제목·재료 텍스트 검색, 삭제(확인 대화상자).
5. **중복 방지**: 같은 제목·같은 재료 구성은 저장 전에 알려 준다.

## 5. 비기능 요구사항
- **저장소**: SQLite 단일 파일(Python 표준 `sqlite3`). 테이블 예: `profile(id=1, nickname, prefs_json)`(1행 고정), `recipes(id, title, data_json, ingredients_json, created_at)`.
- **바인딩**: 서버는 `127.0.0.1`에만 바인딩한다(`0.0.0.0` 금지).
- **입력 검증**: 서버에서 길이·타입을 검증하고, 화면 출력 시 이스케이프한다(저장된 AI 텍스트는 신뢰하지 않는다).
- **비밀 관리**: `.env`와 DB 파일은 `.gitignore`로 커밋 제외한다(`.env`는 이미 제외됨, DB 파일 경로 추가 필요).
- **배포**: 로컬 실행이 기본. 외부 공개 시 HTTPS와 호스팅 디스크 영속성을 다시 검토한다(무료 호스팅은 재시작 시 파일이 사라질 수 있음).

## 6. 범위 밖
- 로그인·다중 사용자, 이메일 인증, 다중 기기 동기화, 레시피 공유, 평점·댓글.

## 7. 성공 기준
- 프로필 생성 → 레시피 저장 → 새로고침/재시작 후에도 목록 유지.
- 서버가 `127.0.0.1` 외에서는 접속되지 않는다.
- 저장·삭제가 즉시 목록에 반영된다.

## 8. 열린 질문
- (결정됨) 로그인 생략, 단일 프로필. 기술 스택은 Python + FastAPI.
- UI는 정적 HTML/JS(프레임워크 없음)로 할지 확인 필요(기본값으로 제안).

## 9. 전체 단계 연결
1단계(재료 인식) → 사용자 편집 → 2단계(레시피 생성) → 3단계(프로필·저장). 재료 목록 JSON과 레시피 JSON이 단계 간 계약이므로 변경 시 세 문서를 함께 갱신한다.
