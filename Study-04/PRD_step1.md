# PRD 1단계: 냉장고 사진 재료 인식

## 1. 목적
사용자가 냉장고(또는 식재료) 사진을 올리면, 비전 모델이 사진 속 식재료를 인식해 목록으로 돌려준다. 이 목록은 2단계(레시피 생성)의 입력이 된다.

## 2. 사용 모델 (확정, 2026-11-23 호출 검증 완료)
| 용도 | 모델 | 비고 |
|---|---|---|
| 이미지 인식 | `nvidia/nemotron-3.5-super-vl:free` | `/chat/completions`, base64 `image_url` |
| 대안(폴백) | `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` | 추론 모델, `max_tokens` 넉넉히 |

- 무료 모델이라 429(속도 제한)가 날 수 있다. 재시도(지수 백오프, 최대 3회) 후 폴백 모델로 전환한다.
- 이미지 모델이 추론형일 경우 `content`가 `null`로 올 수 있으므로 `max_tokens`는 1000 이상으로 한다.

## 3. 사용자 스토리
- 사용자는 사진 파일을 선택하거나 끌어다 놓아 업로드한다.
- 사용자는 인식된 재료 목록을 보고, 잘못 인식된 항목을 지우거나 빠진 항목을 직접 추가한다.
- 사용자는 확정한 재료 목록으로 2단계로 넘어간다.

## 4. 기능 요구사항
1. **업로드**: JPEG/PNG/WebP, 최대 10MB. 클라이언트에서 긴 변 1280px 이하로 리사이즈 후 전송해 토큰과 지연을 줄인다.
2. **인식 요청**: 서버가 이미지를 base64 data URL로 모델에 전달한다. 프롬프트는 "사진에 보이는 식재료만 JSON으로" 요구한다.
3. **구조화 출력**: 모델 응답을 아래 JSON으로 파싱한다. 파싱 실패 시 1회 재요청, 그래도 실패하면 오류 안내와 수동 입력 화면으로 전환한다.
   ```json
   { "ingredients": [ { "name": "계란", "quantity": "약 6개", "confidence": "high|medium|low" } ] }
   ```
4. **편집 UI**: 항목 삭제, 이름·수량 수정, 직접 추가. `low` 신뢰도 항목은 시각적으로 구분한다.
5. **오류 처리**: 429/네트워크 오류/빈 결과 각각에 대해 사용자 메시지를 구분한다.

## 5. 비기능 요구사항
- **키 보호**: `OPENROUTER_API_KEY`는 서버에서만 읽는다(`.env`). 브라우저로 키를 내려보내지 않는다.
- **개인정보**: 업로드 이미지는 인식 요청 후 저장하지 않는다(메모리에서만 처리).
- **응답 시간**: 목표 30초 이내(무료 모델 대기 포함). 진행 표시를 보여 준다.
- **비용**: 무료 모델만 사용, 요청에 `:free` 접미사를 반드시 유지한다.

## 6. 범위 밖
- 재료 양의 정밀 추정, 유통기한 인식, 영수증 인식.
- 다중 사진 일괄 처리(후속 과제).

## 7. 성공 기준
- 식재료 5종 이상이 보이는 사진에서 주요 재료의 대부분이 목록에 포함된다(수동 점검 기준).
- 응답이 유효한 JSON으로 파싱되는 비율이 높고, 실패 시 수동 입력으로 이어진다.
- 429 발생 시 폴백으로 결과가 나온다.

## 8. 열린 질문
- (결정됨) 기술 스택: Python + FastAPI 서버가 OpenRouter를 프록시하고 정적 HTML/JS 화면을 제공한다. 키는 `python-dotenv`로 `.env`에서 읽는다.
- 재료 이름 언어: 한국어 고정으로 할지 확인 필요(기본 한국어 제안).
